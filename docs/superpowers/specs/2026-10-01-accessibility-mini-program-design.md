# 生活服务中心小程序 Demo 设计

## 目标

将当前微信原生 TypeScript 小程序模板扩展为可操作的生活服务中心 Demo，覆盖首页、服务列表、服务详情、设置、个人中心，并增加可从服务详情进入的报名表单演示页。主要目标是让微信读屏用户能够理解页面层级、操作名称和控件状态，并能完成导航、筛选、收藏、设置、媒体浏览和表单校验流程。

## 当前项目

项目使用微信原生小程序技术栈：TypeScript、WXML、WXSS，已有五个生活服务业务页、共享服务数据和本地状态模块。本次继续使用原生页面和组件，新增独立表单演示路由；服务与表单数据保持本地，不接入后端或账号系统。

## 信息架构

- 底部原生 TabBar：`首页`、`服务`、`设置`、`我的`。
- `服务详情`作为普通页面，从首页推荐卡片或服务列表进入；展示有替代说明的图片和可选视频。社区活动详情可进入单独的报名表单页；该页不新增 Tab。
- 报名表单只在本地演示校验与结果反馈，不发送或持久化用户填写的信息。
- 各页面按视觉和读屏阅读顺序组织内容，页面标题通过原生导航栏标题和页内标题共同表达。
- 原有日志页不再作为导航入口；首页继续使用当前 `pages/index` 路径，其余页面使用清晰的业务路径。

## 页面设计

### 首页

- 展示欢迎语、带持久文字标签的搜索输入框、服务分类快捷入口、推荐服务和通知入口。
- 搜索后可进入服务列表查看匹配结果。
- 分类快捷入口切换到服务 Tab，并选择对应分类。
- 顶部使用文字和色块构成生活服务主视觉，不承载只有视觉用户才能获取的信息。

### 服务列表

- 提供关键词搜索、分类单选筛选、结果数量和服务卡片。
- 每张卡片显示服务名称、类别和简短说明；整体操作通过原生按钮进入详情。服务结果卡片使用双列布局。
- 无匹配结果时显示可读的空状态说明和清除筛选操作。
- 搜索与分类筛选使用同一份本地服务数据；结果节点保留在页面内容流中，方便读屏用户按顺序浏览。

### 服务详情

- 展示服务名称、摘要、办理条件、办理步骤、办理时长及联系信息。
- 社区活动详情使用用户提供的本地图片，并同时配置 `src`、`label` 和 `caption`，由图像角色、简洁替代说明和相邻可见图注呈现。
- 视频结构使用原生播放器控件；仅在收到并配置用户提供的可直接播放链接、播放器名称、内容简介和文字稿后显示。当前没有视频对象，详情页只显示素材待提供的普通文字，不渲染播放器或宣称可播放。
- 为“社区活动报名”提供进入表单演示页的原生按钮。
- 通过原生复选控件呈现收藏状态；状态写入本地存储，并同步至个人中心收藏列表。
- 联系入口只展示和说明示例操作，不发起真实电话或外部请求。

### 报名表单演示

- 以“社区活动报名”作为表单场景，使用原生 `form`、`input`、`picker`、`radio-group`、`checkbox-group`、`textarea` 和提交按钮演示常见字段。
- 字段包含必填联系人称呼、活动日期/场次、是否需要无障碍协助，以及可选备注；手机号等个人联系方式不采集。
- 字段均有持久可见的中文标签、说明和必填提示；错误信息显示在对应字段旁，错误控件暴露无效状态并关联错误文本。
- 提交时执行本地必填校验；错误摘要和成功反馈提供可读文本与适当的动态播报。不得请求网络、写入本地存储或暗示真实报名已完成。

### 设置

- 提供“大字模式”和“高对比模式”两个原生开关。
- 设置写入本地存储，并作用于其余页面。页面布局避免固定高度裁切放大后的文字。
- 提供简短的无障碍操作说明，提示页面操作顺序与开关效果。
- 首次启动时使用明确的默认设置（常规字号、标准对比度），原因是新安装用户尚无本地偏好；服务数据的必需字段不做兜底。

### 个人中心

- 使用“示例用户”作为本地示例身份，不请求登录或真实个人信息。
- 展示收藏服务、最近浏览和常用入口；收藏与最近浏览卡片使用双列布局，列表项可以进入服务详情或切换至对应 Tab。
- 没有收藏或浏览记录时显示有说明文字的空状态。

## 数据与交互

- 使用一个共享的 TypeScript 服务数据模块，服务记录包含稳定 ID、名称、分类、摘要、办理条件、办理步骤、办理时长和联系说明等展示所需字段。
- 媒体模型使用可选的 `media`、`image` 和 `video` 对象；`community-events` 已配置本地图片的 `image.src`、`image.label`、`image.caption`，当前没有视频对象。以后只有在用户找到合适素材时才配置 `video.src`、`video.label`、`video.summary`、`video.transcript`；不为缺失字段设置默认值。
- 搜索按服务名称、分类名称和摘要匹配；分类筛选与关键词搜索可以组合使用。
- 推荐项、搜索结果、收藏和最近浏览均从同一组本地服务记录派生，避免不同页面的展示不一致。
- 收藏与设置使用小程序本地存储；最近浏览在打开详情时更新。
- 视频链接不伪造默认值。没有配置完整视频资料时不渲染播放器，详情页保留中文待提供说明；是否接入视频由用户之后的素材选择决定。
- 页面不从外部加载业务数据。视频仅使用用户明确提供的直链；联系、通知等示范入口通过页面内说明或本地弹窗反馈，不触发外部操作。

## 无障碍要求

本 Demo 以微信官方[无障碍访问文档](https://developers.weixin.qq.com/miniprogram/dev/component/aria-component.html)为属性依据。文档说明基础库自 2.7.1 起支持部分 ARIA 属性；`aria-label` 是焦点时附加播报，不等同于可见标签；不同系统对 `aria-role` 播报存在差异。实现中只在确有语义需要的节点添加属性，不把整套属性机械贴到每个节点，也不覆盖原生控件已有的名称、角色和状态。

- 优先使用原生 `button`、`input`、`switch`、`checkbox`、`radio-group`、`picker` 和 `form`，确保可见文字标签与输入项对应；占位提示只补充格式或示例，不代替标签。
- 服务卡片用可见子文本呈现服务名、分类和简介；`aria-label` 用简体中文补充“打开详情”这一操作提示，不重复复制可见卡片文案。通用按钮优先使用可见文本。
- 所有读屏可感知的名称、说明、状态、错误和媒体替代文案均使用简体中文；ARIA 角色、布尔值和关联 ID 保持规范格式。
- 非原生可交互节点使用合适的 `aria-role`、`aria-label` 或 `aria-labelledby`；不把原生控件角色改写成不相容的角色。
- 用 `aria-describedby` 关联输入说明，用 `aria-required`、`aria-invalid`、`aria-errormessage` 表达表单必填和错误状态；错误文本须始终可见，不能只由颜色标记。
- 用 `aria-live`、`aria-atomic` 在动态筛选结果、表单错误摘要和提交反馈处提供有节制的读屏更新；不将整页或每条静态说明设为 live region。
- 通过原生 `checked` 等状态表达收藏、单选和开关状态；只有自绘控件才用相应的 ARIA 状态属性。
- 以 `aria-role="header"` 和 `aria-level` 表达标题层级：页内主标题为 1、区块标题为 2、区块内标题为 3；列表项提供 `aria-posinset` 和 `aria-setsize`；装饰节点使用 `aria-hidden`。
- 图标不单独承担操作名称；有意义的图片提供简洁替代说明和可见图注。视频不开启自动播放，并提供与重要音视频信息等效的文字内容。
- 交互目标采用宽松间距和足够尺寸；正文与背景保持清晰对比，文字支持换行和放大。

| 语义目的 | 文档属性/原生语义 | Demo 使用位置 |
| --- | --- | --- |
| 名称、描述与关系 | 可见 `<label>`、原生按钮文字、`aria-label`、`aria-labelledby`、`aria-describedby`、`aria-errormessage` | 输入字段、服务卡片动作提示、图片、表单错误 |
| 角色与结构 | 原生组件角色；需要时 `aria-role`、`aria-level`、`aria-posinset`、`aria-setsize` | 标题、列表、列表项、示意图片、自绘控件 |
| 控件状态 | 原生 `checked`/`disabled` 等；自绘状态才使用 `aria-checked`、`aria-disabled`、`aria-expanded`、`aria-pressed` | 收藏、分类筛选、设置开关和表单状态 |
| 表单约束 | `aria-required`、`aria-invalid`、`aria-errormessage` | 必填字段和校验失败字段 |
| 动态更新 | `aria-live`、`aria-atomic`、必要时 `aria-relevant`/`aria-busy` | 筛选结果数量、表单错误摘要、提交反馈 |
| 隐藏装饰 | `aria-hidden` | 纯装饰图形和与文字重复的图标 |

只在相应交互或结构确实存在时使用属性；例如本 Demo 没有折叠面板时不添加 `aria-expanded`，原生 TabBar 已提供文字和选中状态时不模拟 `aria-current`。

### 页面节点覆盖

| 页面 | 主要读屏节点与状态 |
| --- | --- |
| 首页 | 页内标题、带可见标签的搜索输入框、带列表位置的分类/推荐卡片、通知说明入口；装饰色块隐藏。 |
| 服务列表 | 搜索输入框、分类单选组、live 结果数量、带列表位置的服务卡片、清除筛选按钮、无结果说明。 |
| 服务详情 | 服务名称和摘要、办理信息标题与步骤列表、收藏复选控件及勾选状态、带替代说明和图注的社区活动图片、视频待提供说明、报名入口；视频素材到位后才出现播放器与文字稿。 |
| 报名表单 | 表单标题、字段可见标签与说明、必填状态、错误信息关联、动态错误/成功反馈和提交按钮。 |
| 设置 | 大字模式和高对比模式开关及开关状态、无障碍操作说明。 |
| 个人中心 | Demo 身份文字、收藏和最近浏览分组标题、带列表位置的详情入口、空状态说明、原生 Tab 切换入口。 |

交互名称通过可见原生标签、按钮文本、`aria-labelledby` 或有必要的 `aria-label` 提供；按微信文档，`aria-label` 是焦点后附加播报的信息，卡片以它补充“打开详情”动作并保留可见名称。原生控件保留其角色和选中状态。页面滚动区域使用 `scroll-view` 的列表语义；仅动态结果与表单反馈配置 live 属性，实际播报仍待运行时验证。

## 视觉方向与资源

- 清爽、克制的生活服务视觉：浅色背景、深色正文、青绿色主色和清晰的卡片分区。
- 页面强调易读性和可触达尺寸，避免信息只靠颜色、图标或图片传达。
- 首页主视觉延续代码绘制的色块与文字；详情页展示用户提供的社区活动图片。使用本地图标的原生 TabBar 保留“首页/服务/设置/我的”文字标签。
- 首页服务分类、首页推荐、服务结果及个人中心服务记录均采用双列卡片布局；按钮按边框盒计算尺寸，放大文字时保持内容换行。

## 文件边界

- `miniprogram/app.json`：注册页面和四项原生 TabBar。
- `miniprogram/assets/tabbar/`：四个 Tab 项的常态与选中态 PNG 图标；文字标签继续提供可读名称。
- `miniprogram/app.wxss`：全局颜色、排版及字号/对比主题样式。
- `miniprogram/pages/index/`：生活服务首页。
- `miniprogram/pages/services/`：搜索、筛选及服务列表。
- `miniprogram/pages/detail/`：服务详情、媒体替代文本、视频文字内容与收藏交互。
- `miniprogram/pages/appointment/`：本地校验的社区活动报名表单演示。
- `miniprogram/assets/`：TabBar 图标与用户提供的社区活动图片；视频链接由用户提供并配置，不提交虚构素材。
- `miniprogram/pages/settings/`：无障碍设置。
- `miniprogram/pages/profile/`：个人中心。
- `miniprogram/data/services.ts`：有类型约束的本地服务示例数据。
- 首页主视觉使用 WXSS 色块构成，无插画资源。
- TypeScript 中的函数、变量及复杂业务逻辑添加简体中文注释。

## 验收标准

1. 微信开发者工具能够编译并进入首页；四个 Tab 页面可互相切换，详情可进入和返回。
2. 首页搜索与分类快捷入口、列表关键词/分类筛选、详情收藏、设置开关、个人中心记录均可按预期操作。
3. 设置、收藏和最近浏览在页面切换后仍正确展示；首次启动有明确的字号和对比度默认值。
4. 每个交互都有可理解的名称；需要时使用文档支持的 `aria-role`、`aria-labelledby`、`aria-describedby`、状态、错误和动态播报属性，不重复覆盖原生语义。
5. 大字和高对比设置作用于所有页面，文字能够换行，不因固定高度被裁切。
6. 表单可在本地演示必填校验、字段错误关联、无障碍协助选择及成功/失败反馈，不联网、不持久化用户输入。
7. 服务详情展示具备替代说明和可见图注的本地活动图片；收到完整视频资料后，使用原生播放器并提供文字稿/字幕等效内容。视频素材验收仍待完成。
8. TypeScript 检查通过。读屏节点与页面层级可在微信开发者工具中逐页检查；屏幕阅读器的实际播报效果仍需真机验证。

## 范围外

- 服务端、登录、真实个人资料、支付和真实联系操作。
- 需要用户提供直链的视频资源；视频结构按可选内容设计。
- 为可访问性承诺特定屏幕阅读器播报细节。开发者工具检查和真机读屏测试分开记录。

## 实施现状补充（2026-10-02）

- 首页、服务列表、详情、设置、个人中心和独立报名页的源码语义已按实际控件调整：可见标签优先，服务卡片仅补“打开详情”动作；标题、列表、列表位置、原生选择状态、输入说明关系、表单字段错误关系和有限的动态播报均有对应 WXML 节点。
- 报名页路由为 `/pages/appointment/appointment?serviceId=community-events`，属于普通非 Tab 页面。表单输入只存在页面内存中；代码不发送、不持久化报名内容，也不采集手机号。
- 社区活动详情已显示本地图片，并有替代说明和可见图注；没有视频资料时显示中文待提供说明。以后找到合适视频时可补齐播放器名称、简介和文字稿；当前不要求为完成 Demo 提供视频。
- 集成 CUA 曾核对首页、服务列表、社区活动详情、报名必填错误和设置开关状态；开发者工具节点树显示中文名称与状态。个人中心完整交互、报名成功状态以及 iOS VoiceOver / Android TalkBack 实际播报仍待验证。源码和模拟器节点树不能替代真机读屏。
